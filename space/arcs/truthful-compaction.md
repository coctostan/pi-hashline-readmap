# Compacted bash output is truthful and recoverable

## Destination
Every bash result a compactor changed states nothing false, drops only noise silently, reports each other drop in `details.rtkCompaction.dropped`, and names a saved copy of the pre-RTK output, so recovery never needs a re-run. Ships as 0.20.0.

## Not yet specified
- Original-output temp files are never cleaned up, like the context guard's today: a cleanup policy when they turn out to pile up
- The linter route grows small inputs (main 2026-11-02: 6 lines of `file:line:col` output became 15): is a summary longer than its input still a compaction?
- From slice 2: with the guard off and Pi truncating, RTK compacts Pi's truncated view, so the marker counts only visible lines (`... and 1919 more lines` of 2500) and Pi's own `Full output:` line can be among the cut ones; the notice still names Pi's full file
- From slice 6: the linter's header counts ESLint unix `[Warning/…]` findings as errors (`N errors, 0 warnings`), a false count that needs a severity parse
- From slice 6: Docker's default BuildKit output names no noise, so a successful BuildKit build passes almost whole (`#N DONE`, layer progress)
- From slice 6: a compaction that saves nothing or grows the output still prints its notice and saves an original (live 2026-11-02: rsync 206 B → 206 B, `git status --ignored` +57%); joins the linter item above
- From slice 9: the build route's status words (`Running`, `Creating`, …) match any line starting with them, so a build script's own `Running out of memory` drops silently; pinning them to cargo's 12-column right alignment would keep it but also stop dropping pip's indented lines
- From slice 9: git's `---`/`+++` headers are dropped before any `diff --git` too, so an unindented `git show --format=%B` message line starting `--- ` drops; drop them only after a `diff --git`
- From slice 10: Pi 1.5.0's abort, timeout and no-exit-code paths throw with the text only (`bash.js:271`, `:275`, `:282`), so a truncated one carries no `details.fullOutputPath`: RTK compacts Pi's visible tail and the notice names a snapshot of it, which still holds Pi's `Full output:` line, so recovery takes two reads; telling Pi's trailing notice from a command's own copy needs Pi's metadata
- From the fourth close: `--color-words` marks old and new words only by colour, and `stripAnsi` in `filterBashOutput` runs on every result before any route, so its lines read `line old1new1`; a pass-through keeps every line but not which words were removed

## Decisions
