# `read`, `edit` and `write` stay Hashline's by default

In the read-and-edit run (gpt-6-luna and Claude Sonnet 5.5, thinking off, 744 runs, $11.16), Hashline's three tools tied Pi's built-ins on pass rate within the spread everywhere but Sonnet's edit control, 98% against 90% for Pi's three (spread 5%). Bash in their place lost gpt-6-luna's locate tasks, 8/20 against 20/20, at about four times the input tokens, and erred more on both models. Against them, Hashline's arm cost Sonnet 7,220 more input tokens an edit-control run than Pi's three (spread 1,494) and drew 0.25 `edit` errors a locate run against none; those the blind review saw were fixed on the next call. The one per-task lead is Hashline's: gpt-6-luna's block copies and deletes passed 8 of 8 with its `edit` and 2 of 16 without, 2 runs a cell. So the defaults stay: Hashline registers all three, `PI_HASHLINE_BUILTIN` remains a bench switch, and Hashline's `edit` is never offered behind Pi's `read`, the arm whose `edit` erred most on gpt-6-luna (0.50 a locate run against 0.10, 0.36 an edit-control run against 0.12) and on Sonnet's edit control (0.14 against 0.05). The run measured short single-purpose tasks only, not long sessions where a file changes under the model; a later run on Opus 5.5 or with thinking on may revisit this.
